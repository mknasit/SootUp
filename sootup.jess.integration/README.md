# SootUp JESS Integration

Integration module for running JESS analysis on Java projects using SootUp.

## Overview

This module enables JESS (Java Equivalence and Similarity System) analysis on **SootUp bytecode**. It uses SootUp's bytecode frontend to analyze Java bytecode, extract methods, and perform similarity comparisons. The analysis works directly on bytecode representations generated by SootUp, allowing you to analyze compiled Java code without requiring source code access.

## Requirements

- **Java**: JDK 17 or higher
- **Maven**: 3.6+ (for building)
- **JESS**: Version 1.0.0 (if not in Maven Central, install locally)

### Installing JESS (if needed)

If JESS is not available in Maven Central, install it locally:

```bash
mvn install:install-file \
  -Dfile=/path/to/jess-1.0.0.jar \
  -DgroupId=de.upb.sse \
  -DartifactId=jess \
  -Dversion=1.0.0 \
  -Dpackaging=jar
```

## Building

Build the project:

```bash
cd sootup.jess.integration
mvn clean package
```

This creates a fat JAR at: `target/sootup.jess.integration-jar-with-dependencies.jar`

## Usage

This tool analyzes **SootUp bytecode** representations of Java methods. It uses SootUp's bytecode frontend to:
- Load and analyze bytecode from JAR files
- Convert bytecode to SootUp's intermediate representation
- Extract methods for JESS analysis
- Compare bytecode similarity

### Option 1: Single Project

Analyze a single project:

```bash
java -jar target/sootup.jess.integration-jar-with-dependencies.jar \
  --repo /path/to/project \
  --ref-jar /path/to/project/target/project.jar \
  --work /path/to/output \
  --pkg com.example.package \
  --limit 100
```

**Required options:**
- `--repo`: Path to project root directory
- `--ref-jar`: Path to the compiled JAR file
- `--work`: Output directory for results

**Optional options:**
- `--pkg`: Package prefix filter (e.g., `com.example`)
- `--limit`: Max number of methods to analyze (default: 100)
- `--debug`: Enable debug output
- `--strict`: Enable strict mode

### Option 2: Multiple Projects (Batch Mode)

Create a JSON config file (`projects.json`):

```json
[
  {
    "name": "Project 1",
    "projectDir": "/path/to/project1",
    "sourceRoots": ["src/main/java"],
    "pkg": "com.example",
    "limit": 100
  },
  {
    "name": "Project 2",
    "projectDir": "/path/to/project2",
    "sourceRoots": ["src/main/java"],
    "limit": 50
  }
]
```

Run with config file:

```bash
java -jar target/sootup.jess.integration-jar-with-dependencies.jar \
  --pcfg projects.json \
  --result-base-dir /path/to/results \
  --debug
```

**Configuration fields:**
- `projectDir` (required): Path to project root
- `name` (optional): Project name
- `sourceRoots` (optional): Source directories, default: `["src/main/java"]`
- `classpathJars` (optional): Additional JAR files for classpath
- `pkg` (optional): Package prefix filter
- `limit` (optional): Max methods to analyze, default: 100
- `workDir` (optional): Output directory, default: `projectDir/pc-out`

## Using Constant Propagation Analysis Programmatically

The module provides an **Intraprocedural Constant Propagation Analysis** algorithm that can be used independently to analyze SootUp bytecode. This analysis performs constant propagation and folding on Jimple statements within a single method using a lattice-based approach.

**Note**: This is an **intraprocedural** analysis, meaning it only analyzes within a single method. It does not propagate constants across method boundaries - method invocations are treated as unknown operations.

### Basic Usage

```java
import com.jessintegration.analysis.ConstantPropagationAnalysis;
import sootup.core.jimple.common.stmt.Stmt;
import java.util.List;

// Get a list of Jimple statements (from SootUp bytecode)
List<Stmt> statements = ...; // Your Jimple statements

// Perform constant propagation analysis
ConstantPropagationAnalysis.ConstantPropagationResult result = 
    ConstantPropagationAnalysis.analyze(statements);

// Access results
int constantsPropagated = result.getConstantsPropagated();
int expressionsFolded = result.getExpressionsFolded();
int deadBranchesRemoved = result.getDeadBranchesRemoved();
String simplifiedSequence = result.getSimplifiedSequence();
List<String> simplifiedTypes = result.getSimplifiedStatementTypes();
```

### Checking for Constant-Producing Operations

Before running the full analysis, you can check if statements contain operations that would benefit from constant propagation:

```java
boolean hasConstants = ConstantPropagationAnalysis.hasConstantProducingOperations(statements);
if (hasConstants) {
    // Perform analysis
    ConstantPropagationAnalysis.ConstantPropagationResult result = 
        ConstantPropagationAnalysis.analyze(statements);
}
```

### Comparing Results

The analysis result can be used to compare two different bytecode implementations:

```java
ConstantPropagationAnalysis.ConstantPropagationResult result1 = 
    ConstantPropagationAnalysis.analyze(statements1);
ConstantPropagationAnalysis.ConstantPropagationResult result2 = 
    ConstantPropagationAnalysis.analyze(statements2);

// Check if results are equivalent
boolean equivalent = result1.isEquivalent(result2);

// Compute similarity score (0.0 to 1.0)
double similarity = result1.computeSimilarity(result2);
```

### What the Analysis Does

The intraprocedural constant propagation analysis:
- **Propagates constants**: Tracks constant values through local variables within a method
- **Folds expressions**: Evaluates arithmetic and bitwise operations at compile time (e.g., `2 + 3` → `5`)
- **Simplifies statements**: Replaces variable uses with their constant values
- **Identifies dead branches**: Can detect branches with constant conditions
- **Intraprocedural scope**: Only analyzes within a single method; method calls are treated as unknown operations

The analysis uses a lattice-based approach with three values:
- `CONST(c)`: Variable has a definite constant value `c`
- `TOP`: Variable has multiple possible values or is unknown (includes method call results)
- `BOTTOM`: Unreachable code or no information yet

### Example

```java
// Example: Analyzing a method's Jimple statements
List<Stmt> methodStatements = method.getBody().getStmts();

// Run constant propagation
ConstantPropagationAnalysis.ConstantPropagationResult result = 
    ConstantPropagationAnalysis.analyze(methodStatements);

System.out.println("Constants propagated: " + result.getConstantsPropagated());
System.out.println("Expressions folded: " + result.getExpressionsFolded());
System.out.println("Simplified sequence: " + result.getSimplifiedSequence());
```

## Output

Results are written to `workDir/out/`:
- `statistics.json`: Analysis statistics
- `methods/`: Per-method results

For batch mode with `--result-base-dir`, aggregated statistics are written to `combined_statistics.json`.

## Notes

- **Bytecode Analysis**: The tool performs analysis on SootUp bytecode representations, not source code. It uses SootUp's bytecode frontend to process compiled Java classes.
- The tool automatically builds projects using Maven or Gradle if JAR doesn't exist
- Projects that fail to build are skipped (use `--debug` for details)
- For large projects, increase heap: `java -Xmx4g -jar ...`
